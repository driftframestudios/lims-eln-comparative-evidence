# Comparative Evidence source authority mapping

## Contract

- **What:** A repository-local method for tracing one material comparison
  object from the source that defines it to the receiver that can act on it.
- **When:** Producer evidence, Comparator-owned snapshots, profiles, schemas,
  generated reports, signed release records, and publication carriers could be
  treated as one authority.
- **Boundaries:** The map records evidenced relations and granted decisions.
  It preserves evidence mode, privacy, release, publication, attribution, and
  production-authorization boundaries. Delivery does not acquire semantic
  authority merely by carrying bytes.
- **Result:** A concise lineage map naming the object, authority roles, typed
  relations, exact coordinates, current receiver, evidence limit, and event
  that reopens the map.

## Rules

### Rule: Begin with one object and decision

Name the exact profile field, observation, snapshot, report fact, artifact,
release coordinate, or projected file whose route changes a decision.

### Rule: Keep authority roles independent

Distinguish producer meaning, Comparator-owned source, schema or profile
authority, evidence admission, report generation, release acceptance,
publication, delivery, and receiving use wherever they diverge.

### Rule: Type each relation

Use literal relations such as defines, snapshots, admits, compares, renders,
releases, projects, preserves exact bytes, or receives. A snapshot retains its
upstream coordinate and remains distinct from an upstream release artifact.

### Rule: Identity and retrieval are different facts

Record semantic digest, release subject, source revision, projected file
identity, docs revision, and canonical URL independently. Stable meaning can
survive a presentation or delivery change.

### Rule: Evidence modes remain visible

Simulated verification, planned contract shapes, and observed evidence keep
their declared provenance and assurance stage. A public projection improves
inspection; it does not change evidence mode or grant production authority.

### Rule: Promotion preserves complete coordinates

A stable receiver records source repository, path, full revision, relation,
report digest, and retained history. Exact runtime-byte claims also record the
projected file's byte identity.

### Rule: Public boundaries remain explicit

Public-ready material may enter a hosted projection. Public-possible skills
remain in the repository workbench until a separate review accepts their
reader job and publication posture.

### Rule: End at a receiving decision

The map ends in a concrete move: retain the source, correct a binding, admit an
observation, regenerate a report, publish accepted bytes, defer a projection,
or return a question to the source owner.

## Operating sequence

1. Name the object and decision.
2. Locate its defining source and exact coordinate.
3. Trace only the transformations and receivers that affect the decision.
4. Separate semantic, schema, admission, generation, release, publication, and
   delivery roles.
5. Confirm the receiver's required identity and evidence posture.
6. Choose the smallest correction, projection, handoff, or deferral.
7. Preserve coordinates, evidence limits, and the event that reopens review.

## Completion

The map is ready when another collaborator can identify what defines the
object, what validates and accepts it, which representation is current, what
the public or downstream carrier establishes, and who can make the next
decision.
