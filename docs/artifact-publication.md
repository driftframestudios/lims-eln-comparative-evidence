# Complete comparison and evidence publication

`write_reports` prepares the released JSON and HTML bytes, writes a private
sibling directory, and verifies the report digest and exact HTML projection.
It publishes the two files through one directory rename. The report retains
exactly `comparison.json` and `comparison.html`; the administrative study's
three-file profile keeps its [separate source-bound contract](administrative-evaluation.md).

Supply an absent or empty report directory. An existing empty directory,
including a `TemporaryDirectory` root, remains supported. A completed directory
accepts an identical generated-byte replay. A changed report or foreign entry
preserves the existing output and returns an action to choose a fresh directory.
Callers migrating from populated-directory overwrite can retain each result
under a new run directory, or explicitly clear output they own before calling
again. A final symlink remains an occupied entry. Published directories and files
retain private staging permissions (0700 and 0600); a delivery owner can grant
its intended readers access after verification.

Observed and selected-future admission use the same private staging ownership.
They verify the complete serialized manifest, then create its final name with
an exclusive hard link. Readers therefore encounter either an absent final
name or complete JSON. Identical generated bytes return the accepted path;
changed bytes retain the prior manifest and require the namespace's new-identity
route. Generated bytes remain those of the released serializer. Manually
reformatted or edited manifests receive the occupied-entry response, making
replay identity explicit and bounding each read by the prepared payload size.

## Recovery and ownership

The caller controls the parent directory. Legacy entry points resolve parent
aliases once, then traverse the concrete path through directory descriptors;
final entries retain their collision boundary. This preserves conventional
macOS temporary paths and existing caller-selected parent aliases. The
administrative publisher retains its stricter concrete-parent requirement.
Independent publishers acquire distinct private names. Receivers inspect a
quiescent bundle. Another actor with permission to rename entries in the same
parent has authority beyond this cooperative publication protocol.

A caught write, verification, or publication failure releases invocation-owned
staging and permits retry at the same unoccupied destination. SIGINT is delayed
across acquisition/publication bookkeeping, so a pending interrupt can report
whether complete output became visible. SIGTERM retains the process's chosen
handler; abrupt termination can leave `.artifact-pending-*` directories.
A later invocation owns a different staging name and leaves retained staging
available for local inspection. The owner can verify final artifacts and remove
that specific retained directory after confirming its invocation has stopped.

`PublicationError` records `stage`, `published`, `pending_name`, and any
`cleanup_error`. Admission preserves this diagnostic as its exception cause.
KeyboardInterrupt/SystemExit retain publication state and a pending name;
secondary cleanup observations stay attached to the primary failure. A cleanup
failure after successful publication retains complete accepted bytes. Retry
can establish their identical identity while the owner separately resolves the
reported staging cleanup.

Files and the staging directory are synced before publication, and the parent
is synced afterwards. A later sync failure reports visible complete output.
Native macOS interruption and competing-writer tests exercise these paths;
the Linux exclusive-rename ABI follows the existing source-reviewed helper.
Hardware power-loss durability, arbitrary network-filesystem behavior, and
hostile same-authority namespace mutation require their own observations.

## Work and retained bytes

Writing, hashing and equality checks are linear in the admitted JSON and
rendered HTML bytes. Sorted JSON serialization also performs key-ordering work:
for objects with k keys, the comparison cost sums k log k across those objects,
alongside byte traversal. Report preparation retains one input tree and
both output byte strings. Independent candidate verification reads one member
at a time, parses one report tree, and renders its HTML twin. That work has
linear peak storage with transient UTF-8/text/render copies; it establishes
exact semantic projection before publication. Manifest verification compares
bytes directly, avoiding another parsed manifest tree. Collision checks read
at most each prepared member's byte count plus one and inspect at most one
extra directory entry. These are per-input bounds; input admission owns the
size of the original evidence.
